# Generate ideas (a living pool, fantasy first, no subagents)

Everything runs in the main session. **No subagents** (user, 2026-11-10: "the skill now should not work
with multiagent"). The critic role from `~/.claude/RULES.md` rule 13 is an inline pass in the checks.
Read `lessons.md` here first: it holds how ideas work, why they fail or pass, and every method change.

The user's direction (2026-11-11): "keep improving the passing ones and keep fixing the failing ones and keep
adding more and more as well and keep expanding understanding as well on how ideas work and how to improve
methodology". So the work is a **cycle** over a **living pool**, repeated as long as the user wants.

## The pool
`~/Playground/game-design-research/research_notes/Idea search/pool.md`, one file:
- **Passed:** the current [job] [choice] [goal] line, its weak spots (~), and the check table row.
- **Failed:** the idea itself, the check where it stopped and why, and how many fixes it has had.
- **Dropped:** ideas that failed 2 fixes, with the reason (kept so they are not re-invented).
- **Cycle log** at the end: one short entry per cycle (what was fixed, improved, added, learned, changed).

## The cycle (each step in order; one cycle per run unless the user says more)
1. **Fix the failing ones.** For each failed idea, write one fix aimed at the exact check it failed (change
   the job, the choice, the goal, or the setup), then recheck. After 2 failed fixes, move it to Dropped.
   An idea that died at the probe gets **one** fix only (cycle 3: 1 of 8 such fixes passed; ideas that failed
   later checks were fixed 4 of 4 in cycle 1).
2. **Improve the passing ones.** Take away one ~ per idea: sharpen the choice (section C), or remove the
   content or lag risk behind a ~. Recheck what the change touches. First apply the fixes the Rules critics named
   for ideas leaning ✗. After any fix that moves the danger, recheck that the job still pulls the danger in (cycle 16:
   a wandering moonbeam let the crew stir when it was elsewhere).
   - Content fix that worked (cycle 2): freeze the opposition or give it one rule (ghosts stand still, guests
     sit, raiders walk straight). The cheapest opposition is a cursed friend.
   - **Rule step:** for 2 older passing ideas still marked "needs a rule", write the one-sentence rule (at most
     2 extra rules) in the pool's Rules section, then run the critic on the rule (`checks.md` 4.6). A rule can
     demote an idea (cycle 3: Hypnotist's Show), or show it is a skin of a core.
   - **Sweeps (added cycles 7–10):** once a cycle, over every core, re-run every probe lesson: a solo exit (a way out
     without the friend), a safe spot (a place the threat can't reach), a dump (one player soaking up the harm), help
     that costs only time (one player becomes the helper), one resource handed around, identical players, anyone
     idle at 6, harm decided by a dice roll, a goal that rules out one side of the choice. Old passes predate later
     lessons. Cheap, and catches most holes before a scene.
   - **Scene step (added cycle 6):** for 4 cores a cycle, play one scene in words at 3 players and one at 6: who
     stands where, what each sees and says, the choice each makes, what goes wrong. Write it under the core in the
     pool's Scenes section and fix or mark what it shows (`design-anti-patterns.md` C: play one scene).
   - **Long scene (added cycle 13):** for 3 top cores a cycle, play round 1, round 5 and round 20 in words: what the
     crew does differently by round 20, and what stops them settling into a habit (`checks.md` 4.4). After a fix,
     play it again, up to 3 times, until no new habit shows (added cycle 20; the critic rule in `RULES.md` 13 asks the
     same).
3. **Add new ideas.** 6–10 new fantasies through sections A–D, aimed at the failure the pool shows most, and at
   a choice shape and a look the pool has few of (count the Shape column; the pool leaned night-time curses).
   - **Rule at birth:** every new idea that passes gets its rule and the critic on it in the same cycle.
   - **When it saturates (added cycle 15):** after 5 cycles with 0 new cores, write full lines for skins of the
     strongest cores instead (fantasy options for a rule that works); go back to new fantasies after 3 cycles or when
     the user asks for new cores.
   - **Attractors:** when 3 or more pool ideas share one skeleton, add it to `lessons.md`'s taken list and aim
     away from it (cycle 3: P, and T as "take it onto yourself, or hurt them to end it").
   - **Cores (added cycle 4):** the pool is grouped by core (ideas whose rule is the same). A new idea on an old core
     is a skin: list it under that core, and don't count it as new. The cycle's score is new cores.
4. **Expand the understanding.** Write into `lessons.md` what this cycle showed about how ideas work: which
   fixes worked and why, what the passing ideas share, which choice shapes hold up. If the search budget
   allows, research one open question about it and cite the sources.
5. **Improve the method (automatic, user-approved 2026-11-11: "could you also auto improve the skill itself
   if it is working?").**
   - **Measure last cycle's changes first.** Each open entry in `lessons.md` → "Method changes" names the
     failure it targets. Compare that failure's count with the cycle before, **counting only ideas made or
     changed after the change** (old ideas it never touched don't measure it; added cycle 2). Fewer: mark it
     **kept**. Same or more: **revert** it (copy back from `history/`) and mark it **reverted**, with the numbers.
   - **Then make new changes.** If a lesson shows a gap (a check missed something, a step keeps producing the
     same failure), copy `SKILL.md` and `checks.md` to `history/<name>-<date><letter>.md`, edit them, and log the
     change: date, what changed, the gap it targets, the count to beat, and "result: pending".
   - Gaps noticed but not fixed this cycle go to `lessons.md` → "Open gaps".
   - Tell the user what changed and what was kept or reverted, one line each.

## How to make and check an idea (used in steps 1–3)
### A. Fantasy
- One line: who you are and what you're doing, where the story puts players' bodies, lives or abilities in
  each other's hands. Lean toward help that **spreads** harm (curses, taints, infections, scratches).
  Skip families `lessons.md` lists as taken.
- **"My X does Y to you" (added cycle 24):** write the spatial relation between two friends first (my steps turn your
  floor, my gaze freezes you, my voice pushes you, my shadow is your floor), then a fantasy where it is natural. This
  gave 2 new cores in 6 after 5 cycles of at most 1. The player's own camera and microphone count as tools.
- **Couplings of space** (who stands where; every move frees or blocks a friend) held up best by cycle 8; meter
  couplings (cold, fur, fever) need something dealt to stop "share evenly". Space fails when it makes one queue or one
  slot.
- **Optional starting points** (each tried for one cycle, none beat the others): a friend-verb the pool lacks (new
  cores so far came from new verbs: push off, swap places, carry for sight, unbolt a part, make room); real animal
  or human rituals (the hermit crab vacancy chain); researched folklore (gave harms, not verbs). Note which one each
  fantasy came from.

### B. Why interact (the force)
**What makes me need a friend right now?**
- **A pressure that grows on its own** (air, hunger, cold, fire, a sinking floor). Without it nothing forces
  the interaction (plain Vampire Family: "feeds only on each other" says where blood comes from, not why now).
- **Only a specific friend's act relieves it,** not the world or an item.
- **Relieving it costs or risks that friend**, ideally because **the harm spreads onto the helper**.
- **Something new is dealt each round:** who gets hit, which harm, how strong.
- **Fixed-plan probe (now, not at the end):** write the plan the crew would use by round 5. Drop or rework if it
  is "take turns", "share evenly", "nearest helps", "hand it to whoever is farthest", "decoy", or a
  **threshold** ("pass it at half", "stop at three"). A threshold is fine only if something dealt each round,
  or what a friend just did, moves where the right threshold is.
  Also a **role split** ("one wrapper, everyone else digs", "one guard with scissors"): when helping costs only
  time, one player becomes the helper. The help must cost the helper's body. And **interchangeable players
  rotate**: if every player is the same, "swap when blue" wins; players must differ by what the crew did to them.

### C. The idea line: [job] [choice] [goal], natural sentences
The user's format (2026-11-10/11: "this is way much beter"; "include some sort of main choice to make in the
game.. [job] [choice] [goal]").
- **Job:** what you do when nobody is in trouble; best when the job itself pulls the danger in, so more
  progress means more danger.
- **Choice:** the main decision a player makes again and again, written as "X, or Y". Both sides cost
  something. **A friend must be in the choice:** one side is an act on a specific friend, or letting a friend
  act on you (three ideas lost their friend when first written this way). Prefer a choice only this fantasy
  can give; most ideas share "push your luck, or pass the harm to a friend".
- **Goal:** what these people want in the story. Not a generic timer, not a place to reach (a level = content).
- Concrete words: physical actions and named things, never "fight it", "help" or "deal with". Never "risk", "may" or
  "might" for a harm without saying what decides it; those words hid dice rolls in 3 lines (cycle 12). Adding detail to
  the same line is not an improvement (user: "is exactly the same").
- You may change a fantasy's setup to make the goal fit; say so.
- **Shape tag:** P push or pass · T two ways to help · U use a friend · S swap harms · W where to put it (on which
  part of the friend). New shapes get a new letter in the pool's list.
- **Look:** one line on what the screen shows; it must show the state the choice depends on (`checks.md` 2b).

Example: *Sin Eaters: Swallow the sin-worms from the dead man's coffin; you only learn which sin you swallowed
when the stain appears. Keep your stain and risk being dragged into the coffin, or let a friend draw half off
with bread, knowing that if it is Wrath it swings at them first. Swallow every worm before the rooster crows.*

### D. Check
- `checks.md` here, in order; the first ✗ stops the idea. Score what the line gives; mark "needs a rule"
  instead of inventing one. A short reason for every ~ and ✗.
- **Critic pass:** for each survivor, the plan the crew settles into by round 5 and the one-line trick that
  beats it. If there is one, "no fixed plan" is ✗.
- **Honest labels:** Claude writes and scores, so it isn't blind. Novelty: search the theme as well as the
  mechanic (cycle 13: 3 themes were already on stores with different mechanics). Novelty: web search within the budget
  (200 WebSearch calls per session, shared, ~100 per hour refill; never work around the limit), otherwise
  "memory (unchecked)".

## Files and report
- **Where things are saved:**
  - Ideas: the pool file (above), with its cycle log.
  - Understanding, method changes (with results) and open gaps: `lessons.md` here.
  - Old versions of the skill: `history/` here.
  - One line per cycle: the project's `research.md`.
  Why files: the chat gets summarized and a new session can't see it.
- Report with the `explain-simple` skill: answer first, plain words, no analogies. Then:
  - **Passed:** each [job] [choice] [goal] line, marking what changed this cycle.
  - **Failed:** the idea itself, then the check where it stopped and why. Never just a name.
  - **Learned** and **method changes:** one line each.
