# The user's model of conscious and unconscious thinking (2026-11-19)

Built by the user over one chat, starting from "everything under a conscious methodical procedure is always superior".
Use their words: orchestrator, interface, raw power, shaped db, shapeless db, RAM.
Picture: `conscious-unconscious-model.png` (source `.svg`) in this folder.
The research behind the ✅/❌ lines is in `breaks-vs-more-work.md`.

## The two environments
| | Unconscious | Conscious |
|---|---|---|
| What it is | the raw power (user) | the orchestrator interface (user) |
| Role | produces the ideas and points at where to look | the steering (Claude; the user first said "never the drive"): holds the goal, works one idea out step by step, rejects what fails |
| How it runs | in the background, many things at once | one step at a time |
| Short-lived memory | temporary state that only shapes its next result and can't be read (Claude) | working memory, "RAM": a few items for seconds (Claude added it, the user adopted it) |
| Long-lived memory | the unconscious db, shapeless from the interface side (user); it holds patterns that behave like rules, not rules written out (Claude) | the shaped db: you can recall it and work on it (user) |

Psychology's names: explicit memory (shaped db), implicit memory (unconscious db), working memory (RAM). (from memory)

## The links
- Every conscious step is handed up by the unconscious: which thought comes next, "this follows", "this is off". (Claude, accepted)
- The interface sends a request built from the goal and the approach it is holding, and gets back results only.
- Practice moves a skill from conscious to unconscious.
- Feedback from the world tunes the unconscious db; a hunch is only good where there was a lot of practice with fast, clear feedback.
- A worded rule is a second copy in the shaped db that describes the pattern and can be wrong.
- The test "you can say how you got there, so it was conscious" is too weak (user caught it): the story can be written after the result.
  Better test: the steps were in mind before the result.

## What goes wrong
- **Fixation:** the orchestrator holds one approach, so every request brings back ideas near it.
- **Made-up story:** the interface can't read how a result was made, so it writes an explanation afterwards; the user compared it to AI hallucination.
- **Overthinking:** the orchestrator keeps running after it stopped improving the result; the cause is often an unconscious "this isn't settled" that keeps handing the thought back.
- **Choking:** the orchestrator steers a skill the unconscious runs better alone.

## Creativity
- In order: load the problem with hard work (conscious), the idea arrives (unconscious), work it out and check it (conscious).
- A conscious method can't do the exploring; it can change the request (drop an assumption, flip the problem, borrow from another field). (Claude, from memory)
- Two kinds of stuck: not enough work yet (keep working), and repeating (a short easy break, or a forced different start). ✅ researched
- The feeling of being stuck misleads both ways. ✅ researched
- The unconscious working a new problem alone in the background: ❌ least supported.

## The same shape in an AI loop (user's comparison, Claude's table)
| Human | AI loop |
|---|---|
| unconscious thinking | the model writing its next output |
| unconscious db | the model's weights |
| working memory | the context window |
| conscious thinking | the orchestrator loop |
| learned methods and habits | the harness: rules and skills |
| thinking about thinking | the harness improving itself |

The user rejected "a generator with a checker around it" as the software match: running tests is the world giving feedback, not conscious thinking.
